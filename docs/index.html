Evaluated on a time-based holdout (most recent academic year), not a random split, since a random split would leak recurring course/instructor grade patterns across train and test. Baseline and training are both weighted by section enrollment — an unweighted row-count majority-class baseline came out to 75.8%, inflated by tiny always-A independent-study sections outnumbering large lecture courses in raw row count.

Pipeline

Madgrades API and RateMyProfessor's GraphQL endpoint feed raw JSON into date-versioned GCS storage. A BigQuery pipeline flattens per-section grade distributions, fuzzy-matches instructors across the two sources (no shared ID between them), and builds a course-offering-level feature table. XGBoost is tuned with Optuna and every run is tracked in MLflow. A Dockerized Cloud Run Job, triggered weekly by Cloud Scheduler, keeps the dataset current.

Full source, commit history, and every real bug found while building this (API field-name mismatches, a case-sensitivity bug in the instructor fuzzy-matcher, a Cloud Run OOM, etc.) are on github.com/RithikGobinath/CourseIQ.
